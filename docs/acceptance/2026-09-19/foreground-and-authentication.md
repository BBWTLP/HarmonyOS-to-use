# 前台身份与应用隐私密码验收

日期：2026-09-19（Asia/Shanghai）；JSON 报告时间为 UTC。设备为当前 USB 连接的 HarmonyOS 6.1 真机。本轮仅使用微博、小红书及必要的系统诊断；未发布、评论、点赞、关注或修改账号设置。

## 结论与证据边界

无密码屏幕锁恢复已通过独立三轮验收，平均客户端调用 4396 ms，含唤醒、解锁和 FAST 读屏。后续 Runtime 观察会先检查屏幕状态，需要时尝试无凭据恢复；仅在确认亮屏且未锁屏后继续。见 [解锁记录](automatic-wake-unlock.md)。

小红书另有系统应用隐私密码保护。实际启动已执行，但未进入可验证的小红书业务页面。新增检测后约 7093 ms 返回 `authentication_required`，保留 `execution_status=executed`、`verification_status=inconclusive`；跨应用验收按失败记录。不能把此结果称为小红书验收通过，也不能用关闭屏幕锁密码来推断应用隐私密码已关闭。证据：[app-switch-metadata.json](app-switch-metadata.json)。

随后通过 Runtime 启动微博并验证前台。实际 stdio MCP 的搜索验收中，“启动微博”和“进入发现页”均通过，客户端动作耗时分别 6797 ms、6953 ms。接下来的搜索栏点击被 `stale_observation` 阻止：三次重新观察后仍发生页面变化，四次尝试均在派发前拒绝，搜索流程未完成。证据：[weibo-search-metadata.json](weibo-search-metadata.json)。该报告对应其中记录的脚本哈希，当前脚本另增加了失败动作状态保留。

最后一次独立 FAST 实时检查返回：`screen_on=true`、`screen_locked=false`、微博前台身份一致、`actionable=true`、137 个控件、采集 2515 ms、无应用密码弹窗，且无未决动作。会话已正常关闭。

## 实现与验证

- 前台识别通过窗口焦点与 Mission/Ability 的明确字段交叉检查；焦点前后变化、重复记录、状态不匹配均不声称前台应用已确认。此对应关系已在当前真机上验证，不能据此声称所有 HarmonyOS 设备均已覆盖。
- 采集前后前台信息不同则观察不可操作、不进入动作缓存。同一控件树换到其他应用时旧观察不可用于动作；已实现 bundle 后置条件及有明确基线的 app_changed 等待。
- 系统应用认证识别同时要求系统包、认证扩展、密码标题和密码输入控件。只允许返回、主屏幕和启动应用等离开弹窗的动作；点击、输入和滑动在日志入场及派发前被拒绝。已派发的启动遇到认证页时立即结束验证并记录事件，不自动重放。
- Weibo 验收脚本在非启动动作前、动作结果后检查微博前台、采集稳定性和认证状态。即使派发后验证失败，也保留执行状态；报告仅包含元数据。
- probe 经真实 stdio MCP 读取工具返回的文本/图片块，而非直接服务调用推测协议结果。动态发现页实际返回图片，但 `image_tree_consistent=false`，因此报告 `not_ready`。FULL/SoM 仍待在稳定业务页面真机通过，不能将图片传输成功等同于图树一致。

完整回归：146 项通过（23.490 秒），`pip check` 通过。覆盖前台变化、未知身份、认证派发前拦截、启动后认证拦截与幂等、等待不误判、错误前台拒绝，以及认证失败状态保留且不重放。真机失败与未验收项不会被单元测试通过覆盖。

前后台端点采样不能证明整个区间没有发生 A→B→A 切换；未实现连续系统事件证据。屏幕自动恢复、前台验证、页面稳定性和应用业务认证分别判定。当前性能尚不满足“响应极快”，保留原有页面/目标过期校验。
