## 当前真机证据的边界

- 真机 FAST/FULL 观察是只读采样，不是业务任务成功率；未操作应用，不证明微博搜索输入或跨应用长任务。
- 批处理后 FULL 第三次因 actionable=false、image_tree_consistent=false、som_available=false 被安全拒绝；仅凭 image_present=true 不能将其判为通过。
- 热状态、页面动态、网络、应用版本、冷/热启动条件未控制；六组各三次只能作为工程诊断证据，不能外推正式 P95。
- 小红书应用隐私密码和微博动态 stale_observation 仍是明确阻塞；不会通过放宽指纹校验、盲重试或自动输入凭据掩盖。
- Agent transport 成功不能替代动作/业务闭环；当前真机已通过 `On.text` → `Driver.findComponents` 最小只读语义探针，但这不等于点击、输入、导航、截图、微博搜索或首客户端验收通过。

## 审计时原拟顺序（已由用户后续指令调整，保留历史）

1. 在当前真机固定一个无私人内容、稳定且可重复的页面，先完成基线、前台、屏幕和认证状态的受控矩阵。
2. 用同一页面和同一条件对照批处理前后阶段耗时；只有重复样本显示收益才继续优化，当前不声称提速。
3. 单独修复图树/SoM 稳定性和动态页面目标定位，再做微博输入闭环；认证拦截继续保持停止语义。
4. 先核对 `Driver.getDeviceInfo` 的当前真机/DevHelmKit 契约并复测 Agent 语义，再按 v2 顺序推进 OCR/CV、Provider/Planner/Checker、未知写入可信对账、证据回放和正式 30/100/300 验收。

本审计是当前实现的工程状态和差距记录，不是完整项目验收，也不是“鸿蒙版 Artemis 已完成”的声明。
