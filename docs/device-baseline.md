# 当前真机开发与验收基准

决策日期：2026-09-19。来源：用户明确更正“验收与系统都以我当前的真机为准”。

## 口径

- 首期开发、适配和验收以当前授权连接的真机为唯一设备基准；不把 HarmonyOS 6.0、6.1 或其他固定版本写成硬性前置条件。
- 当前真机本轮只读基线同时记录“设备软件发行版本”和“底层 OpenHarmony 构建字段”，二者含义不同，不能互相替代：软件发行版本为 SGT-AL10 6.1.0.135(SP8C00E120R3P11)，底层字段为 OpenHarmony-6.1.1.120 / incremental 6.1.1.120。
- 当前基线证据：[批处理后真机基线](acceptance/2026-09-19/device-baseline-20260919-batched.json)。生成时间为 2026-09-19 11:32:44–11:32:45（Asia/Shanghai）；基线 ID 为 b2ea4e54d37fadec2c03acb012e51c3cdb4d4afbd0f7fd2766df373e62df4da1。
- 该基线是环境元数据，不等于业务验收通过。任何设备、系统、应用、工具链、连接方式或源码状态变化，都必须生成新基线并重跑受影响门槛。
- 不自动绕过系统锁屏、应用隐私密码或其他凭据保护。允许已实现的无凭据唤醒/解锁；认证受阻必须明确报告并等待用户处理。

## 未测与不可推断项

本轮基线没有主动连接、部署、RPC、关闭设备连接、唤醒、解锁或读取 UI；它只执行固定白名单只读命令。因此以下项目仍为 not_measured：显示分辨率与缩放、应用版本、前台与认证状态、HDC 传输方式、设备端协商协议、设备加载的 agent 哈希、任务成功率、受控冷/热延迟。

“驱动推测协议 2”不是协议协商结果；“本地 agent 资产哈希”不是手机加载证明；phone_operation_verified=false、acceptance_verified=false 必须保留。当前真机 FAST/FULL 观察小样本见 [观察基准记录](acceptance/2026-09-19/benchmark-observation-20260919.md)，不能替代 v2 的正式原语、任务和发布门槛。

## 采集命令

在项目目录、已授权 HDC 设备连接状态下执行：

    .\.venv\Scripts\python.exe -m harmony_runtime.cli baseline --execute --state-dir .runtime\acceptance

该命令缺少 --execute 时退出 2；发现设备不唯一或只读基线不可用时退出 1；成功退出 0。命令不需要常驻 Runtime 服务，也不执行 UI 动作。输出只应保存为本机 .runtime/ 的白名单元数据报告，再经过隐私审查后进入验收材料。

## 关联验收规则

v2 的原语各 100 次、20 状态、M1 30 次至少 27 次成功、固定 30 任务/100 步/300 次正式验收仍是项目门槛。真机小样本只能说明当前连接和观察路径的已知行为，不能把环境基线或单元测试通过解释为 Artemis 等效完成。
