### 2.3 关键机制（均已实现并有单测）

- 候选与观察 id、控制 epoch、参数引用、有效期绑定；派发前 Guard 复核 `target_ref` 与局部指纹。
- 未校准模型不得 `execute`（`DecisionResult` 语义校验）；影子模式零派发。
- 未知写入分 `execution_status` / `verification_status` 两轴，进入 `RECONCILIATION_REQUIRED` 不自动重放。
- 任务状态机（QUEUED/RUNNING/VERIFYING/PAUSED/WAITING_USER/RECONCILIATION_REQUIRED/CANCELLING/终态），
  重启不自动续跑，暂停/取消/恢复有界。
- 工件 TTL/配额/路径防护，未决记录与去重墓碑不参与回收；脱敏导出不含文本与图像。
- 只读 CLI：`agent tasks / task / artifacts / replay`（分页有界、缺失工件显式标记、不开放公网）。

### 2.4 本轮修复的真实缺陷（7 项）

1. Runtime 在持有运行时锁时调用 HDC 发现设备 → 移到锁外。
2. 工件存储 SQLite 跨线程无锁 → `check_same_thread=False` + 锁。
3. `mobile_decide` 返回 pydantic 对象导致服务端 JSON 序列化失败、客户端丢响应 → `model_dump()`。
4. 设备 worker 被隔离时会话状态不体现 → 新增 `device_state` / `worker_quarantined`。
5. 分层定位未登记可点击祖先 → 文本标签不可点击时召回恒为 0，已按 `parent_action_id` 上溯。
6. 验收 harness 无读超时、MCP 服务端 stderr 无人读取 → 加读超时并落盘 stderr。
7. harness 未处理运行中出现的 `device_quarantined` → 自动 `recover` 后重试未派发的调用。

## 5 验收计划（真机恢复后按此顺序执行）

### 5.1 前置：环境与冻结

```powershell
# 1 设备与工具链
hdc list targets                       # 必须恰好一台
.\services\decider\Start-Decider.ps1 ; .\services\decider\Test-Decider.ps1   # ok=true 才算就绪

# 2 冻结实现（A01）
python .\scripts\evidence_manifest.py --report docs\acceptance\<日期>\baseline-manifest.json
python .\scripts\reproduce.py          # 346 项回归
```

**纪律**：不要在验收过程中强杀真机进程；一旦强杀，必须先重启 Runtime 服务再继续
（否则残留租约 300 秒 + worker 隔离会污染后续批次）。

### 5.2 顺序与判据

| 顺序 | 验收 | 命令（要点） | 判据 |
|---|---|---|---|
| 1 | M0 原语矩阵 | `accept_m0_primitives.py --execute --per-primitive 100` | 每原语成功率 ≥99%，失败逐条保留 |
| 2 | C01 分段性能 | `accept_c01_benchmark.py --execute --samples 100` | 热 P50/P95 + 失败分母；冷基线需另做受控流程 |
